# Phase 2 모듈 3 — 이벤트 원문 감성 스코어링 완료 리포트

생성 시각: 2026-08-14

## 개요

`collect_events.py`가 수집한 US 8-K(7,944건)/KR 주요사항보고·수시공시(22,490건) 원문을 문장 단위로 쪼갠 뒤 슬라이딩 윈도우(window=3, stride=1, 겹침)로 묶어 각각 감성 스코어링하고, 문서 하나의 최종 점수로 집계했다.

- **US**: `yiyanghkust/finbert-tone` (BertForSequenceClassification 직접 로드)
- **KR**: `snunlp/KR-FinBert-SC` (AutoModelForSequenceClassification)
- **집계식**: `score = mean(P(Positive) - P(Negative))` (윈도우별로 계산 후 평균), 범위 -1~1
- 문서 전체(512토큰)를 통째로 넣으면 신호가 뭉개져 전부 Neutral로 나오는 걸 실증 확인 후 문장 단위 슬라이딩 윈도우로 설계 확정(상세 근거는 `phase2_sentiment_scoring_handoff.md` 참고)

### 알려진 한계

한화에어로스페이스 사례는 "불성실공시", "위반", "지연" 같은 표면적으로 부정적인 어휘가 포함돼 있지만, 실제 내용은 "**미지정**"(제재 대상으로 지정되지 **않음**), "벌점 미부과"로 회사에 유리한 결과다. KR-FinBERT가 이런 **이중부정 규제 표현**을 제대로 못 읽고 어휘 표면에 반응해 오분류한 것으로 판단된다. 코드 버그가 아니라 일반 금융감성분류 모델의 알려진 한계이며, 별도 규칙 기반 보정 없이 그대로 사용한다(Phase 1에서 51~55% 방향성 정확도를 현실적 한계로 받아들인 것과 같은 원칙 — 완벽한 신호를 억지로 만들려 하지 않는다).

## 실행 중 발견·수정한 버그

로컬 CPU 파일럿에서 전체 규모(특히 US) 외삽 시 약 10일이 걸릴 것으로 추정되어, 사용자 승인 하에 속도 최적화를 시도했고 이 과정에서 실제 버그들을 발견해 수정했다.

1. **미니배치 부재로 인한 CPU 정체**: exhibit이 큰 8-K는 윈도우가 최대 1,000개 이상 나오는데, 전체를 한 번에 배치 추론하면 CPU에서 10분 이상 정체(RSS 4.5GB). `score_windows`에 미니배치(batch_size=16)를 적용해 해결 — 결과는 수학적으로 동일, 순서만 배치 단위로 나뉨.
2. **US 네트워크 세션 미재사용**: SEC EDGAR 요청마다 새 TCP/TLS 연결을 맺어 일부 filing이 865초까지 걸리는 걸 확인. `requests.Session` 재사용으로 약 7배 개선(111초/건 → 8~60초/건).
3. **KR 네트워크 세션 미재사용**: US에만 세션 재사용을 적용하고 DART(KR) 쪽은 빠뜨렸던 걸 뒤늦게 발견 — 같은 Session 객체를 SEC/DART가 공유하도록 통일.
4. **KR XML 선언 파싱 버그 (진짜 원인, 실패 1,009건)**: 일부 DART 문서 원문이 `<?xml version="1.0" encoding="euc-kr"?>`로 시작하는데, 이미 EUC-KR로 디코딩한 Python 문자열에 이 선언이 남아있으면 lxml이 "이미 유니코드인데 인코딩 선언이 있는 건 모순"이라며 파싱을 거부(`ValueError: Unicode strings with encoding declaration are not supported`). KR 22,490건 중 1,009건(4.5%)의 실패 원인이었다. 이미 올바르게 디코딩된 문자열에서 선언 줄만 정규식으로 제거하도록 수정, 재현 테스트 2건 추가. 재실행으로 1,009건 전부 해결.

CPU(로컬) → GPU(Colab, Tesla T4) 전환도 병행했다: `event_sentiment_scoring.py`에 디바이스 자동감지를 추가해 CUDA 있으면 int8 양자화 없이 fp32로 GPU 사용(batch_size 64→128로 조정), 없으면 기존 CPU 양자화(onednn 엔진) 경로를 그대로 쓴다.

**변경하지 않은 것**: window_size=3/stride=1, 문장 단위 슬라이딩 윈도우 설계, 집계 수식(`mean(P(Positive)-P(Negative))`) — 전부 사용자가 확정한 그대로 유지. 위 수정은 전부 추론/네트워크 "실행 방식"에 대한 것이지 감성 스코어링 "방법론"을 바꾼 게 아니다.
