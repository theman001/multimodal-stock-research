# Cherry Quant — 핵심 알고리즘 & 전략 정리

> 출처: [위키독스 "Cherry Quant"](https://wikidocs.net/148475) (챕터 001~018, 국내외 블로그·논문 스크랩 모음)
> 이 문서는 원본에서 **재사용 가능한 알고리즘/전략 로직만** 추출·정리한 것입니다. 도구 사용법(트레이딩뷰, 차트 라이브러리 등)은 우선순위가 낮아 [`tools_usage.md`](./tools_usage.md)로 분리했습니다.
> 본 저장소는 ML 기반(XGBoost) 익일 등락 확률 예측 파이프라인(`CLAUDE.md` 참고)이라, 아래는 **규칙 기반 팩터 전략**이라는 점에서 접근 방식이 다릅니다. 다만 백테스팅 검증 원칙(look-ahead bias, 과최적화, 다중비교 보정 등)은 이 프로젝트의 `leakage-guard` 스킬과 사상이 동일해 교차 참고할 가치가 있습니다.

## 1. 알고리즘 트레이딩 표준 프로세스

모든 퀀트/알고리즘 트레이딩 시스템은 4단계로 구성된다:

1. **전략 인식 (Strategy Identification)** — 가설을 세우고 포트폴리오 내 다른 전략과의 상관성, 검증 데이터 확보 방법을 검토
2. **전략 백테스팅 (Strategy Backtesting)** — 과거 데이터로 성과를 검증. MDD(최대낙폭), Sharpe Ratio, K-Ratio 등 계량 지표로 평가
3. **자동화매매 시스템 (Execution System)** — 수동/반자동/완전자동 3단계. 저빈도(LFT)는 반자동, 고빈도(HFT)는 완전자동이 일반적
4. **위험 관리 (Risk Management)** — 최적자산배분, 최적베팅비율(Kelly Criterion 등), 멘탈(심리) 관리

거래비용은 사소해 보여도(1~10bp) 누적수익률에 몇 %~몇십 % 차이를 만들 수 있어 백테스트에 반드시 반영해야 한다.

## 2. 팩터 기반 퀀트 전략 구축 알고리즘 (핵심)

가장 실전적인 부분. 아래 순서로 전략을 **단계적으로 쌓아 올리는** 것이 핵심 원칙이며, 각 단계에서 실제 백테스트 수치(코스피/코스닥, 2007~2021)로 개선 효과를 검증한 예시가 함께 제공된다.

```
1) 팩터 선정
2) 팩터 성과를 상위/하위 정렬로 검증 (매수·매도 로직은 아직 걸지 않음)
3) 보유 기간(리밸런싱 주기) 조절
4) 마켓 타이밍 적용
5) 필터링 조건 추가
6) 매수/매도 조건 최적화
```

### 2.1 팩터 선정과 검증

- **팩터(factor)**: 초과수익을 낼 것으로 기대되는 인자. 가치·재무 지표뿐 아니라 기술적 지표, 비가격 지표, 복합 지표도 모두 팩터가 될 수 있음
- 검증 방법: 유니버스 중 팩터값이 가장 높은 N개 vs 가장 낮은 N개로 포트폴리오를 구성해 성과 비교. 보통 **N=30~50** (너무 적으면 변동성·통계적 신뢰성 저하)
- **중요**: 이 단계에서는 매수/매도 세부 로직을 걸지 않는다 — 팩터 자체의 순수 효과와 로직 효과를 뒤섞으면 어떤 것이 성과를 만들었는지 알 수 없기 때문
- 예시 결과 (저PER 50종목 vs 고PER 50종목, 250일 보유): CAGR 16.6% vs 8.6% (약 2배 차이), 단 MDD -64% → 실전 투입 전 추가 개선 필요

### 2.2 리밸런싱 주기 조절

- 절대적으로 우월한 주기는 없음(연구상 결론) — 트레이드오프의 문제
  - 주기가 길수록: 세금·수수료·슬리피지 절감 / 분산 효과 감소, 수익 변동성 증가
  - 주기가 짧을수록: 분산·리밸런싱 효과 극대화 / 회전율 증가로 비용 상승
- 예시: 같은 저PER 전략을 250일 → 20일 리밸런싱으로 변경 시 누적수익률·CAGR·MDD **모두 개선** (포트폴리오 교체 빈도가 12배 늘어나며 분산 효과도 12배 증가)
- 일반적 권장: 월 단위(약 20거래일) 또는 분기 단위

### 2.3 마켓 타이밍

- 하락장에서는 종목 간 상관계수가 급증해 아무리 분산해도 포트폴리오 전체 손실을 피할 수 없음 → 마켓 타이밍으로 하락 구간 자체를 회피
- 가장 단순하고 로버스트한 구현: **지수 이동평균선 돌파 여부**
  ```
  코스피 종가 > 코스피 20일 이동평균선  → 매수 허용
  코스닥 종가 > 코스닥 10일 이동평균선  → 매수 허용
  (둘 중 하나라도 미충족 시 매수 중단 / 청산)
  ```
- 핵심 관점: "완벽한 타이밍을 찾는 것"이 목적이 아니라 **반드시 주기적으로 오는 대폭락 구간(5~10년 주기)을 피하는 것**이 목적. 불완전해도 있는 것과 없는 것의 차이는 크다
- 예시 효과: 마켓 타이밍 미적용 대비 MDD가 극적으로 감소하면서 **수익률도 함께 상승**(통상 MDD 감소는 수익률 저하를 동반하는 것과 대비되는 결과)

### 2.4 비대칭 진입/청산 원칙 (시스템 트레이딩 공통 철칙)

> **"진입은 신중하게, 청산은 신속하게"**

- 대칭 전략(진입·청산 동일 기간 지표)보다, **진입 조건은 길게(엄격하게) / 청산 조건은 짧게(민감하게)** 설정하는 비대칭 전략이 일반적으로 더 낫다
- 구현 예:
  ```
  진입 조건: A and B  (코스피 20일선 위 AND 코스닥 10일선 위 — 둘 다 충족해야 진입)
  청산 조건: A or B   (둘 중 하나라도 이탈하면 즉시 청산)
  ```
  또는 단일 지수 기준 비대칭:
  ```
  진입: 종가 > 20일 이동평균선
  청산: 종가 < 10일 이동평균선
  ```
- 터틀 트레이딩(20일 신고가 진입 / 10일 신저가 청산)도 동일 원리
- 예시 효과: 2008년 금융위기·2020년 코로나 구간을 포함해도 **MDD 10% 미만**까지 개선

### 2.5 필터링 조건 추가

- 필터링 조건은 팩터와 **독립적인** 것을 추가하는 것이 원칙. 초보자가 흔히 하는 실수는 "좋은 조건"을 욕심껏 다 추가하는 것 — 조건을 모두 만족하는 종목 수가 급감해 오히려 통계적 신뢰성과 수익률이 저하됨
- 효과적인 접근: 아주 좋은 것만 고르기보다 **아주 나쁜 것만 걸러내는(filtering out) 방식**이 실전에서 더 유효
- 검증된 필터 2종:
  - **턴어라운드 필터**: 최근 분기 영업이익 흑자 전환 종목만 포함 → CAGR은 소폭 감소하지만 MDD가 -7% 수준까지 드라마틱하게 감소
  - **소형주 필터**: 시가총액 하위 25%만 포함 ("소형주 효과" — 전세계 주식시장에서 검증된 대표적 알파 요인) → CAGR 42%까지 상승, MDD -10% 이하 유지

### 2.6 종합 알고리즘 (의사코드)

```
for each rebalancing_date (예: 20일 주기):
    universe = KOSPI + KOSDAQ 전종목 (ETF 제외)
    filtered = universe.filter(팩터 조건: 예) PER 하위 50, 시총 하위 25%, 최근분기 흑자전환)

    if 코스피종가 > 코스피_MA20 and 코스닥종가 > 코스닥_MA10:
        진입 허용 → filtered 종목 매수 (전일 종가 대비 -1.5% 지정가 등)
    if 코스피종가 < 코스피_MA10 or 코스닥종가 < 코스닥_MA10:
        전량 청산

    보유 종목은 다음 리밸런싱까지 유지, 주기마다 filtered 재계산 후 교체
```

## 3. 기술적 지표 알고리즘

### 3.1 이동평균 (SMA / EWMA)

- **SMA (Simple Moving Average)**: `SMA_n = (1/n) * Σ Price_i` — 후행성이 있으며, 윈도우가 작을수록 노이즈가 크고, 극단값에 민감
- **EWMA/EMA (Exponentially Weighted Moving Average)**: 최근 값에 더 큰 가중치 부여. pandas `ewm()` 기준:
  ```
  y_t = (1 - α) * y_(t-1) + α * x_t     (adjust=False)
  ```
  `α`는 span, center of mass, half-life 중 하나로 지정 가능. SMA의 지연(lag) 문제를 완화
- 크로스오버 전략 예: 30일 MA가 90일 MA를 하회 → 매수 / 상회 → 매도 (SMA·EMA 동일 로직 적용 가능)

### 3.2 RSI (Relative Strength Index)

```
RSI = AU / (AU + AD)
AU = 특정 기간 상승폭의 합, AD = 하락폭의 합
```
- 통상 **70 이상 = 과매수(하락 압력 증가 신호)**, **30 이하 = 과매도(상승 확률 증가 신호)**
- 한계: 박스권(횡보) 구간에서는 신호가 왜곡됨 — 추세장/횡보장 판단은 별도로 필요

### 3.3 K-Ratio 팩터 (모멘텀 팩터)

- 특정 기간의 일간 수익률 누적 인덱스를 만들고, 시간(X축) vs 인덱스(Y축)로 회귀분석 → **회귀선 기울기 / (회귀 잔차의 표준편차)**로 계산
- 단순 수익률 기반 모멘텀(시작·끝 값만 사용)보다 **중간 경로의 안정성까지 반영**해 더 우수한 백테스트 성과를 보이는 것으로 소개됨

### 3.4 기타 팩터 아이디어 (언급만 되고 상세 공식은 원문에 없음)

- **Equity Duration 팩터**: 금리 민감도 측정 → 금리 인상기에 낮은 duration 종목 선별에 활용
- **RIM 기반 Upside Potential 팩터**: 잔여이익모델(RIM/S-RIM) 기반 적정주가 대비 상승여력 산출 — 단순 PER/PBR보다 가치주 판별에 효과적이라고 소개

## 4. 리스크 관리 / 자금 관리

### 4.1 Kelly Criterion

- 에드워드 소프가 블랙잭 카드카운팅에서 처음 정식화 — "덱에 유리한 카드가 많이 남았을 때 베팅을 늘리고, 불리할 때 줄인다"는 원리를 주식/파생상품 자금배분으로 확장
- 정보(edge)의 크기를 베팅 비율로 환산하는 최초의 정량적 방법론. 실전에서는 순수 Kelly보다 보수적으로(Half-Kelly 등) 적용하는 것이 일반적 (원문에서는 원리만 소개, 축소 적용은 업계 관행으로 별도 언급)

### 4.2 위험 관리 3대 요소

1. **최적자산배분** — 자산군·전략·시점 분산 (Markowitz, 1952 이래 표준)
2. **최적베팅비율** — Kelly Criterion, Optimal f, 2% Rule 등
3. **멘탈(심리) 관리** — 시장은 "동물적 기상(Animal Spirit)"에 의해 움직이므로, 알고리즘의 합리성으로 인간의 비합리성을 포착하는 것이 알고리즘 트레이딩의 본질. 백테스팅에 대한 확신이 없으면 단기 손실 구간에서 전략을 이탈하게 됨

## 5. 백테스팅 검증 체크리스트 (과최적화 방지)

퀀트 백테스팅에서 반드시 점검해야 할 10가지 원칙. **이 프로젝트의 `leakage-guard` 스킬(look-ahead bias, embargo, Bonferroni 보정 등)과 사상이 직접 겹치므로 특히 참고할 가치가 있음.**

| # | 원칙 | 요지 |
|---|------|------|
| 1 | 데이터를 의심하라 | 무료 데이터는 정제도가 낮고 생존자 편향이 있을 수 있음 |
| 2 | Look-ahead bias 금지 | 매매 시점에 알 수 없었던 정보(예: 미래 시가총액 순위)로 과거를 테스트하지 말 것 |
| 3 | 과최적화 회피 | out-of-sample 데이터로 검증. 파라미터를 데이터에 맞춰 짜맞추지 말 것 |
| 4 | 검증 기회는 단 1회 | walk-forward testing, K-fold 등으로 train/val/test 엄격 분리 — 검증 데이터를 두 번 보면 오염됨 |
| 5 | 시대는 변한다 | 20년 전 백테스트가 현재에도 유효하다는 보장 없음 (제도·거시경제·시장구조 변화) |
| 6 | 절제 | 백테스트를 반복할수록 과최적화 위험이 커진다는 것을 자각할 것 |
| 7 | 비퀀트적 언어로 설명 가능해야 함 | 논리로 설명 못 하면 데이터 스누핑(우연한 발견)일 가능성이 큼 |
| 8 | 다각도로 의심하라 | 백테스트 통과 = "나쁘지 않다는 것을 반증하지 못함"이지 "좋다는 증명"이 아님. 비용 가정 조정, 파라미터 스윕, 매매 타이밍 변화, 통계적 노이즈(Bootstrapping) 추가로 안정성 재확인 |
| 9 | 벤치마크를 올바르게 설정 | 예: 기술성장주는 나스닥과 비교해야지 S&P500과 비교하면 안 됨 |
| 10 | 전략을 분산하라 | 전략 간 상관관계를 낮춰 포트폴리오 단위로 리스크 분산 |

## 6. 시스템 아키텍처 설계 원칙 (참고용 요약)

- **관심사 분리(Separation of Concerns)**: 데이터 수집/저장/백테스터/전략파라미터/포트폴리오구성/리스크관리/실행 컴포넌트를 독립 모듈로 분리 — 특정 컴포넌트 교체가 다른 부분에 영향을 주지 않도록
- **리서치 vs 실행 시스템은 언어/기술스택이 달라도 무방**: 리서치(백테스터)는 개발속도 우선(Python/R), 초고빈도 실행은 성능 우선(C++)이 일반적 조합
- **로깅·모니터링·백업을 설계 초기 단계부터 고려**해야 함 (사후에 추가하려면 이미 늦음)
- 저빈도 전략은 "가장 단순하게 만들고 병목이 보일 때만 최적화"하는 것이 합리적 (Knuth의 "premature optimization is the root of all evil")
